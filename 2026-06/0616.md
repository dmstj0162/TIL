## Native Query

- JPQL은 Entity 기준으로 조회하고, Native Query는 실제 DB 테이블/컬럼명으로 조회한다

1. nativeQueryByResultType()
<pre><code>
    // tbl_menu에서 메뉴 하나를 조회하는 SQL
    String query = "SELECT menu_code, menu_name, menu_price, category_code, orderable_status"
        + " FROM tbl_menu WHERE menu_code = ?";
</code></pre>

- Native Query 결과를 Entity로 받으려면, Entity에 필요한 컬럼을 전부 조회해야 한다.

2. nativeQueryByNoResultType()
<pre><code>
    String query = "SELECT menu_name, menu_price FROM tbl_menu";
</code></pre>

- Menu.class를 지정하지 않는다. 그러므로 JPA는 어떤 Entity에 담아야 하는지 알 수 없기 때문에 결과를 List<Object[]> 형태로 반환한다.

<pre><code>
    Object[] row = result.get(0);

    row[0] // menu_name
    row[1] // menu_price

    처럼 배열에서 직접 꺼내 사용해야 한다.
</code></pre>

3. nativeQueryByAutoMapping()

- 이 메서드는 조금 더 복잡한 SQL을 사용하는 예제

<pre><code>
    SELECT 
        a.category_code, 
        a.category_name, 
        a.ref_category_code, 
        COALESCE(v.menu_count, 0) menu_count 
    FROM tbl_category a 
    LEFT JOIN ( 
        SELECT COUNT(*) AS menu_count, 
        b.category_code 
        FROM tbl_menu b 
        GROUP BY b.category_code 
    ) v 
        ON (a.category_code = v.category_code) 
        ORDER BY 1;

</code></pre>

- 이 SQL이 하는 일

* 각 카테고리의 정보를 조회하면서 해당 카테고리에 메뉴가 몇 개인지도 같이 조회한다.

## COALESCE()

- COALESCE(v.menu_count, 0)

- 메뉴가 없는 카테고리는 COUNT 결과가 NULL이 되는데,

- NULL 대신 0을 출력하도록 만들어 주는 함수이다.
