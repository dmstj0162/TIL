# 1. 프로그램이 동작하기 위한 중요한 물리적 자원 3가지

## CPU

CPU(Central Processing Unit)는 프로그램의 명령어를 실제로 실행하고 계산하는 장치입니다.

### 역할

- 연산 수행
- 명령어 실행
- 프로그램 실행 순서 제어

> CPU는 컴퓨터의 **두뇌** 역할을 합니다.

---

## 메모리(RAM)

RAM(Random Access Memory)은 현재 실행 중인 프로그램과 데이터를 임시로 저장하는 공간입니다.

프로그램을 실행하면 저장장치에 있던 프로그램이 메모리로 올라오고, CPU는 메모리에 있는 데이터를 읽어 작업을 수행합니다.

### 특징

- 휘발성 메모리
- 읽기/쓰기 속도가 매우 빠름
- 실행 중인 프로그램 저장

---

## 보조기억장치

보조기억장치는 프로그램과 데이터를 장기간 저장하는 공간입니다.

대표적인 예시

- SSD
- HDD

### 특징

- 비휘발성 저장장치
- 전원이 꺼져도 데이터 유지

---

## 프로그램 실행 과정

```
SSD(HDD)
      │
      ▼
RAM(메모리)
      │
      ▼
CPU가 명령어 실행
```

# 2. 운영체제의 역할

운영체제(OS)는 사용자와 하드웨어 사이에서 컴퓨터 자원을 관리하는 시스템 소프트웨어입니다.

대표적인 운영체제

- Windows
- Linux
- macOS

---

## 1) 프로세스 관리

- 프로그램 실행
- CPU 스케줄링
- 프로세스 생성 및 종료

---

## 2) 메모리 관리

- 메모리 할당
- 메모리 회수
- 메모리 보호

---

## 3) 파일 시스템 관리

- 파일 생성
- 삭제
- 읽기
- 저장

---

## 4) 입출력 장치 관리

- 키보드
- 마우스
- 프린터
- 모니터

등의 장치를 관리합니다.

---

## 5) 보안 및 권한 관리

- 사용자 인증
- 파일 접근 권한 관리

---

## 한 줄 정리

> 운영체제는 CPU, 메모리, 저장장치 등 하드웨어 자원을 효율적으로 관리하여 프로그램이 안정적으로 실행될 수 있도록 지원합니다.

---

# 3. 프로세스와 스레드

## 프로세스(Process)

프로세스는 **실행 중인 프로그램**입니다.

예를 들어 크롬을 실행하면 하나 이상의 크롬 프로세스가 생성됩니다.

### 프로세스가 가지는 메모리 영역

- Code
- Data
- Heap
- Stack

프로세스는 각각 독립적인 메모리를 사용합니다.

---

## 스레드(Thread)

스레드는 **프로세스 내부에서 실제 작업을 수행하는 실행 단위**입니다.

하나의 프로세스는 여러 개의 스레드를 가질 수 있습니다.

---

## 스레드가 공유하는 영역

- Code
- Data
- Heap

각 스레드는 자신만의

- Stack
- Register

를 가집니다.

---

## 프로세스와 스레드 비교

| 구분        | 프로세스           | 스레드      |
| ----------- | ------------------ | ----------- |
| 의미        | 실행 중인 프로그램 | 실행 단위   |
| 메모리      | 독립적             | 공유        |
| 생성 비용   | 큼                 | 작음        |
| 데이터 공유 | IPC 필요           | 공유 메모리 |
| 안정성      | 높음               | 낮음        |

---

## IPC (프로세스 간 통신)

프로세스끼리는 메모리를 공유하지 않기 때문에 IPC를 사용합니다.

대표적인 방법

- Pipe
- Socket
- Shared Memory
- Message Queue

---

## 한 줄 정리

> 프로세스는 실행 중인 프로그램이고, 스레드는 프로세스 내부에서 실제 작업을 수행하는 실행 단위입니다.

---

# 4. 경쟁 조건(Race Condition)과 교착 상태(Deadlock)

# 경쟁 조건(Race Condition)

여러 스레드가 하나의 공유 자원에 동시에 접근하여 실행 순서에 따라 결과가 달라지는 문제입니다.

예시

```
count++;
```

실제로는

```
1. count 읽기
2. +1 수행
3. 저장
```

으로 동작합니다.

두 스레드가 동시에 실행하면 값이 하나만 증가할 수도 있습니다.

---

## 경쟁 조건 해결 방법

### synchronized

```java
public synchronized void increase() {
    count++;
}
```

---

### Lock

```java
Lock lock = new ReentrantLock();
```

---

### Atomic 클래스

```java
AtomicInteger
AtomicLong
```

원자적 연산을 제공합니다.

---

### 불변 객체 사용

객체 자체를 변경하지 않도록 설계합니다.

---

### Thread Local 사용

스레드마다 독립적인 데이터를 사용합니다.

---

# 교착 상태(Deadlock)

두 개 이상의 스레드가 서로 상대방이 가진 자원을 기다리면서 영원히 실행되지 못하는 상태입니다.

예시

```
Thread A
Lock1 보유
↓
Lock2 대기

Thread B
Lock2 보유
↓
Lock1 대기
```

둘 다 상대방을 기다리므로 프로그램이 멈춥니다.

---

## 교착 상태 발생 조건

### 1. 상호 배제

한 번에 하나의 스레드만 자원을 사용

---

### 2. 점유와 대기

자원을 가진 채 다른 자원을 기다림

---

### 3. 비선점

강제로 자원을 빼앗을 수 없음

---

### 4. 순환 대기

서로가 가진 자원을 기다림

---

## 교착 상태 해결 방법

### 자원 획득 순서 통일

항상

```
Lock1
↓

Lock2
```

순서로 획득하도록 합니다.

---

### Lock 범위 최소화

필요한 부분에서만 Lock을 사용합니다.

---

### tryLock() 사용

```java
lock.tryLock();
```

일정 시간이 지나면 포기하도록 구현할 수 있습니다.

---

### 중첩 Lock 최소화

Lock 안에서 또 다른 Lock을 잡지 않도록 설계합니다.

---

## Race Condition vs Deadlock

| 구분 | Race Condition | Deadlock       |
| ---- | -------------- | -------------- |
| 원인 | 동시에 접근    | 서로 기다림    |
| 결과 | 데이터 오류    | 프로그램 멈춤  |
| 해결 | 동기화         | Lock 순서 통일 |

---

# 5. 동기(Synchronous)와 비동기(Asynchronous)

## 동기(Synchronous)

작업이 끝날 때까지 기다렸다가 다음 작업을 수행합니다.

```
작업 A

↓

완료 대기

↓

작업 B
```

### 장점

- 코드가 단순
- 순서를 이해하기 쉬움
- 오류 처리 쉬움

### 단점

- 오래 기다릴 수 있음
- 응답 속도가 느려짐

---

## 비동기(Asynchronous)

작업 완료를 기다리지 않고 다른 작업을 수행합니다.

```
작업 A 요청

↓

작업 B 수행

↓

작업 A 완료

↓

결과 처리
```

### 장점

- 응답 속도가 빠름
- 오래 걸리는 작업 처리에 적합
- 서버 자원을 효율적으로 사용

### 단점

- 코드가 복잡
- 오류 처리 어려움
- 실행 순서를 예측하기 어려움

---

## 동기 vs 비동기

| 구분      | 동기             | 비동기                 |
| --------- | ---------------- | ---------------------- |
| 결과 대기 | O                | X                      |
| 코드 흐름 | 단순             | 복잡                   |
| 응답 속도 | 느릴 수 있음     | 빠름                   |
| 사용 예   | 일반 메서드 호출 | 이메일 발송, 메시지 큐 |

---

## 블로킹과 논블로킹

동기/비동기와는 다른 개념입니다.

### 동기·비동기

> 결과를 누가 처리하는가

### 블로킹·논블로킹

> 작업 중 현재 스레드가 멈추는가

일반적으로

```
동기 + 블로킹

비동기 + 논블로킹
```

조합이 많지만 반드시 함께 사용되는 것은 아닙니다.

# 면접 한 줄 답변

### 프로그램 실행

> 프로그램은 저장장치에 저장되어 있다가 실행되면 RAM으로 올라오고, CPU가 이를 읽어 실행합니다.

### 운영체제

> 운영체제는 CPU, 메모리, 저장장치 등의 자원을 효율적으로 관리하여 프로그램이 안정적으로 실행될 수 있도록 지원합니다.

### 프로세스와 스레드

> 프로세스는 실행 중인 프로그램이며, 스레드는 프로세스 내부에서 실제 작업을 수행하는 실행 단위입니다.

### 경쟁 조건

> 여러 스레드가 공유 자원에 동시에 접근하여 실행 결과가 달라지는 문제이며 synchronized, Lock, Atomic 등을 통해 해결할 수 있습니다.

### 교착 상태

> 서로가 가진 자원을 기다리며 프로그램이 영원히 진행되지 않는 상태이며 Lock 획득 순서를 통일하거나 tryLock 등을 사용하여 예방할 수 있습니다.

### 동기와 비동기

> 동기는 작업이 끝날 때까지 기다린 후 다음 작업을 수행하는 방식이고, 비동기는 기다리지 않고 다른 작업을 수행한 뒤 결과를 나중에 처리하는 방식입니다.
